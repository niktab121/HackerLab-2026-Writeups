## 4. Extraction, étape par étape

### seq 1 : extensions X.509 personnalisées

```bash
for f in certificates/*.pem; do
  openssl x509 -in $f -noout -text | grep -q 99999 && {
    echo "== $f"; openssl x509 -in $f -noout -subject
    openssl x509 -in $f -noout -text | grep -A1 99999; }
done
```

Quatre certificats ont une extension `1.3.6.1.4.1.99999.x`. Deux portent un seq 1 :
- cert_021 (`shared-proxy.merovia.int`) : `{"seq": 1, "val": "MEROVIA_INT"}`
- cert_146 (`interceptor.tsd.valdoria.gov.vld`) : `{"seq": 1, "val": "VALDORIA_FBI"}`

Les deux ont 10.42.3.88 dans leur SAN. C'est la contradiction à résoudre (section 5).

### seq 2 : LDIF

```bash
grep -A1 "ou: TSD" directory_export.ldif
echo 'eyJzZXEiOiAyLCAidmFsIjogIlRTRCJ9' | base64 -d
# {"seq": 2, "val": "TSD"}
```

Les 18 OU ont chacune un seq 2. On retient celle du département qui possède le relais (voir seq 4).

### seq 3 : SQLite


Les 201 bons de commande portent un seq 3 (BUILDING2, 6, 7, 9...). Seul celui du bon VLD-GOV-PROC-2023-0447 nous concerne.

### seq 4 : AES-128-ECB

Politique (`asset_security_policy.json`) :
- algorithme : AES-128-ECB, padding PKCS7 ;
- clé : `SHA256(purchase_order)[:16]` ;
- sortie : hexadécimal dans `zone_tag`, repéré par `zone_encrypted: true`.

```python
import json, hashlib
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad
for a in json.load(open('asset_inventory.json')):
    if a['ip'] == '10.42.3.88':
        k = hashlib.sha256(a['purchase_order'].encode()).digest()[:16]
        print(a['serial'], a['owner'], a['purchase_order'])
        print(unpad(AES.new(k, AES.MODE_ECB).decrypt(bytes.fromhex(a['zone_tag'])), 16))
```

Résultat : `VLD-TSD-SRV-0088 | TSD-OPS | VLD-GOV-PROC-2023-0447`, puis `{"seq": 4, "val": "SECTOR4"}`.

Ce résultat fait aussi le lien entre le relais, le bon de commande et le département TSD.

### seq 5 : profils APT

```bash
echo 'eyJzZXEiOiA1LCAidmFsIjogIkhJR0hfQ09ORklERU5DRSJ9' | base64 -d
# {"seq": 5, "val": "HIGH_CONFIDENCE"}
```

C'est le seul profil dont `infrastructure_overlap` contient `VLD-GOV-PROC-2023-0447`. Les 7 autres profils ont une confiance low, medium ou inconclusive, sans recoupement.

## 5. Désambiguïsation : Valdoria ou Merovia ?

| Source | Valdoria (cert_146) | Merovia (cert_021) |
|---|---|---|
| Autorité de certification | Valdoria-GOV-CA, PKI gouvernementale | Merovia-INT-CA |
| DNS | `proxy-07.tsd.internal.vld` vers 10.42.3.88, confiance high, 28/10 au 04/11 (couvre le 03/11) | `shared-proxy.merovia.int`, confiance low |
| Inventaire | TSD-SRV-0088, TSD-OPS, bon VLD-GOV-PROC-2023-0447 | Aucune trace |
| Bon de commande | Nordic Systems AB, livré à TSD-OPS | Aucune trace |
| Profil APT | VLD-APT-03 : même bon de commande, TTP concordants | MRV-APT-12 et MRV-APT-19 : aucun recoupement, hébergement commercial partagé |
| Annuaire / maintenance | TSD, Bâtiment 7, Secteur 4, FBI Valdoria | Rien |
| Pare-feu | 10.42.3.88 vers 10.42.5.200:8443 (TSD-SRV-0089, TSD-OPS) pendant 08:12–08:25 | Rien |

**Concordance des TTP de VLD-APT-03 :**
- migration de connexion QUIC : détectée (`quic_migration_detected`) ;
- empoisonnement de cache DNS : confirmé (`dns_spoofing_confirmed`) ;
- certificats issus d'une PKI gouvernementale : cert_146 ;
- nommage `.tsd.internal.vld` : `proxy-07.tsd.internal.vld`.

**Leurres identifiés :**
- cert_021 : fausse piste Merovia. Il est isolé, non corroboré, et la CA n'a rien à faire sur une IP 10.42.x.x valdorienne.
- cert_199 (`edge-cache-07.cloudnet.services`) : CA commerciale avec une IP interne incohérente.
- Le rapport de maintenance mentionne aussi une unité CDU, mais le serveur du relais, TSD-SRV-0088, est entretenu par TSD (technicien J. Krause, superviseur K. Vogt, Bâtiment 7, Secteur 4).

## 6. Conclusion

L'organisation responsable est la **Technical Surveillance Division (TSD) du FBI Valdoria** (Bâtiment 7, Secteur 4). L'attribution est de confiance élevée, car au moins six sources indépendantes convergent (certificat, DNS, inventaire, achats, profil APT, annuaire et maintenance), alors que la piste Merovia ne repose que sur un seul certificat.
