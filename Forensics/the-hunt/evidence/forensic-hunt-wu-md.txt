3. Étape 2 : Analyse de l'application RELAY et de la base SQLite
Inspection de layer_6894/app/app.py :
En lisant l'en-tête du code :

"""Serveur de la plateforme RELAY.

La plateforme ne connait pas l'algorithme de cipher.exe : elle affiche les messages tels qu'ils
ont ete envoyes. En revanche, elle chiffre leur stockage :
  - chaque channel a une cle derivee de son code d'acces (scrypt), jamais stockee en clair ;
  - les messages sont chiffres en base avec cette cle (AES-256-GCM) ;
  - un membre garde la cle du channel chiffree avec une cle derivee de son mot de passe ;
  - les cles dechiffrees ne vivent qu'en memoire du serveur, le temps d'une session.
Sans le code d'un channel ni le mot de passe d'un de ses membres, la base ne revele aucun message.
"""
Paramètres cryptographiques du serveur :
KDF_PARAMS = {"n": 2**15, "r": 8, "p": 1, "maxmem": 64 * 1024 * 1024, "dklen": 32}
CHECK_PLAINTEXT = b"relay-channel-key-check"

def derive_key(secret_value, salt):
    return hashlib.scrypt(secret_value.encode("utf-8"), salt=salt, **KDF_PARAMS)

def unseal(key, blob, aad):
    return AESGCM(key).decrypt(blob[:12], blob[12:], aad)

def message_aad(channel_id, author):
    return f"relay:message:{channel_id}:{author}".encode()

with AD1('/CHEMIN_LOCAL/Téléchargements/thanos_desktop.ad1') as ad1:

6. Étape 5 : Rétro-ingénierie de cipher.exe
En déchiffrant la couche AES-256-GCM des messages avec ces codes de canaux, on obtient des chaînes ressemblant à du base64 mais illisibles (ex: f6Wpx-Z_qjt-1qNq...). C'est le chiffrement propre à cipher.exe.

Analyse du binaire :
objdump -d cipher.exe > cipher_disasm.txt
strings -a cipher.exe | grep -E "^[A-Za-z0-9_-]{64}$"
L'analyse statique et dynamique de cipher.exe révèle :

Alphabet Base64 personnalisé (64 caractères) :

Génération de flux pseudo-aléatoire (Stream Cipher) :
Chaque message chiffré contient un sel aléatoire de 4 octets (BCryptGenRandom) au début du payload.

7. Étape 6 : Script complet de déchiffrement des messages
Voici le script d'automatisation complet qui réalise le déchiffrement de la couche externe AES-GCM puis invoque cipher.exe (ou émule sa logique) pour restituer l'intégralité des échanges :

#!/usr/bin/env python3
import hashlib
import sqlite3
import subprocess
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

DB_PATH = "layer_f613/data/relay.db"

# Codes récupérés depuis channel.pdf
CHANNEL_CODES = {
    1: "<EXPURGE>",
    2: "<EXPURGE>",
    3: "<EXPURGE>",
}

KDF_PARAMS = {"n": 2**15, "r": 8, "p": 1, "maxmem": 64 * 1024 * 1024, "dklen": 32}

def derive_key(code, salt):
    return hashlib.scrypt(code.encode("utf-8"), salt=salt, **KDF_PARAMS)

def unseal_aes_gcm(key, blob, channel_id, author):
    aad = f"relay:message:{channel_id}:{author}".encode()
    nonce = blob[:12]
    ciphertext = blob[12:]
    return AESGCM(key).decrypt(nonce, ciphertext, aad).decode("utf-8")

def decrypt_cipher_payload(enc_text):
    """Invoque cipher.exe via wine pour déchiffrer le payload interne."""
    res = subprocess.run(
        ["wine", "cipher.exe", "-d", enc_text],
        capture_output=True,
        text=True
    )
    return res.stdout.strip()

con = sqlite3.connect(DB_PATH)
cur = con.cursor()

# Récupération des sels des canaux
channels_salt = {}
for cid, name, salt, check in cur.execute("SELECT id, name, key_salt, key_check FROM channels"):
    channels_salt[cid] = salt

# Dérivation des clés de canaux
channel_keys = {
    cid: derive_key(code, channels_salt[cid])
    for cid, code in CHANNEL_CODES.items()
}

print("=== DECHIFFREMENT DU CHAT RELAY ===")
rows = cur.execute("SELECT id, channel_id, author, body FROM messages ORDER BY id").fetchall()

for mid, cid, author, body in rows:
    key = channel_keys[cid]
    relay_payload = unseal_aes_gcm(key, body, cid, author)
    cleartext = decrypt_cipher_payload(relay_payload)
    print(f"[{mid:02d}] [Ch{cid}] {author}: {cleartext}")
